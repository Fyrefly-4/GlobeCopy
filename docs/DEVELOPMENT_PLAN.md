# GlobeCopy MVP 开发步骤

**日期：** 2026 年 11 月 2 日

**开发周期：** 3.5 天

**需求依据：** [PRD](./PRD.md)

**交付目标：** 本机运行，通过真实 DeepSeek API 完成输入、生成、展示与复制。

---

### 一、开发原则与目录

- 前后端分开组织，先约定接口，再按完整流程分阶段联调。
- 优先完成模型适配与受控验证；按最新约定，真实模型调用等待前端完成后一起联调。
- 样例数据仅用于前端布局及受控异常测试，最终验收使用真实 API。
- 需求范围、字段限制与验收细节以 PRD 为准。

```text
GlobeCopy/
├── frontend/       # React、Vite、Tailwind，页面与前端接口调用
├── backend/        # Express，业务接口、模型适配、提示词与校验
├── docs/           # PRD、开发步骤与验收记录
└── README.md       # 环境配置、启动与构建说明
```

### 二、分阶段任务

#### 步骤 1：工程初始化与接口约定（第 1 天）

**前端**

- [x] 初始化 React、Vite、Tailwind 工程，保留不渲染内容的应用入口。
- [x] 配置 `/api` 开发代理，不搭建页面骨架，不预设布局与视觉风格。
- [x] 按 PRD 定义请求、成功结果和错误的调用约定，记录于 `docs/API_CONTRACT.md`。

按最新范围约定，步骤 1 仅完成前端工程初始化；Dashboard 页面及风格在后续页面开发阶段确定。

**后端**

- [x] 初始化 Express，建立环境配置与 `.env.example`。
- [x] 配置 Git 忽略规则，确保真实密钥不进入仓库。
- [x] 建立 `POST /api/localize` 路由及统一错误响应。

步骤 1 已完成：前后端工程、健康检查、开发代理及基础错误响应已验证。阶段 2 已接入模型适配层并移除原临时 501 状态。

**完成标准：** 前后端可分别启动，浏览器能够通过代理访问后端；接口字段与 PRD 一致。

#### 步骤 2：真实模型与核心页面（第 1 天完成接口，第 2 天完善页面）

**前端**

- [ ] 完成商品名称、中文原文、国家及只读语言字段。
- [ ] 完成三部分结果展示，用样例数据检查布局。
- [ ] 封装前端接口调用，替换样例数据接入真实后端。

**后端**

- [x] 实现统一 `localize(input)`，使用轻量 Chat Completions 通用适配层，不引入模型 SDK 或供应商框架。
- [x] 通过环境变量配置 API Key、基础地址、模型和超时，默认 DeepSeek，可更换兼容服务。
- [x] 核对 DeepSeek 官方模型与 JSON 输出文档，编写本地化提示词。
- [x] 完成 JSON 解析、字段类型及非空校验。
- [ ] 前端完成后，通过真实账号确认模型可用性、生成质量及端到端流程。

**当前进度：** 后端阶段 2 实现与受控测试已完成，模型适配层和路由均可工作；测试不访问真实模型服务。真实 API 调用、账号可用性与内容质量尚未验收。

**完成标准：** 后端通过受控响应及本机模拟服务验证成功和异常路径；页面完成后，再通过真实模型返回结构有效且质量可接受的结果。此处按最新约定调整原“第 1 天必须真实调用”的联调时点。

#### 步骤 3：功能完善与联调（第 2 天至第 3 天）

**前端**

- [ ] 完成输入长度校验、字符计数及国家语言联动。
- [ ] 完成加载状态、防重复提交与旧结果清理。
- [ ] 完成复制及成功、失败反馈。
- [ ] 完成字段错误、服务错误、超时和网络失败提示，失败时保留输入。
- [ ] 补充 AI 内容审阅与发送至模型服务的简短说明。

**后端**

- [x] 独立校验输入及国家语言组合（随阶段 2 路由接入完成）。
- [x] 完成超时取消、上游失败及响应格式异常处理（受控测试通过，真实服务待联调）。
- [x] 确保错误响应不泄露密钥、内部堆栈或完整上游响应（受控测试通过）。

**完成标准：** 用户能从页面完成输入、真实生成、查看和复制；主要失败路径有明确反馈，可再次操作。

#### 步骤 4：验收与交付（第 3 天至最后半天）

**前端**

- [ ] 检查笔记本布局、窄屏排列、长文案换行和键盘操作。
- [ ] 检查复制内容与显示内容一致，模型内容按文本安全渲染。

**后端与整体交付**

- [ ] 验证前端构建由 Express 托管，本机同源访问接口。
- [ ] 按 PRD 检查三个市场的语言、事实保留、中文对照和文化说明。
- [ ] 检查空值、边界长度、超长输入、无效密钥、超时及非法模型响应。
- [ ] 检查 Git、前端构建和浏览器业务请求中没有真实模型密钥。
- [ ] 完善 README，记录运行环境、配置、开发启动和构建运行命令。
- [ ] 在 `docs/ACCEPTANCE.md` 记录实际验收结果、演示样例和已知限制。

**完成标准：** 按 README 可启动开发与构建版本，真实生成及主要异常路径通过检查，演示样例就绪。

### 三、时间与范围控制

| 时间 | 核心交付 |
| --- | --- |
| 第 1 天 | 工程、接口约定、通用模型适配与受控验证 |
| 第 2 天 | 页面、交互，页面完成后开展真实模型联调 |
| 第 3 天 | 异常处理、内容检查、构建运行 |
| 最后半天 | 修复、文档、验收记录与演示准备 |

进度紧张时优先减少视觉装饰，不删减真实调用、输入与输出校验、错误处理和启动说明。不增加登录、历史记录、流式输出、批量生成或公网部署。

本清单用于后续开发跟踪；已勾选项表示对应工作已实现，整体验收仍以 PRD 和后续验收记录为准。
